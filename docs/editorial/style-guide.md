# Style Guide

## Voice

Use precise, direct language. Introduce the problem before jargon. Distinguish facts, design guidance, and speculation. Avoid anthropomorphism when it obscures mechanisms.

## Mobile-first writing

- One main idea per section
- Paragraphs usually under five lines on a phone
- Descriptive headings rather than “Overview” everywhere
- Tables only for genuinely comparable fields
- Collapsible details for vendor steps, proofs, and optional depth
- A recap or practice prompt after dense material

## Code

Prefer the smallest executable example. State assumptions, pin important dependencies, avoid real credentials, include expected output, and explain educational simplifications.

## Sources

Prefer papers, specifications, official documentation, and reproducible repositories. Link claims near the text they support. Never treat a vendor marketing comparison as neutral evidence.

## Terminology

Define acronyms on first use. Use “model” for the learned artifact, “system” for model plus surrounding components, “agent” for a system that chooses actions in a loop, and “workflow” for an explicitly controlled path.
