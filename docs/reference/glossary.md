# Glossary

Alphabetical definitions for AIEBOK catalog terms. See [concept cards](../concepts/cards/index.md) for expanded entries.

- **A:** A* expands the lowest estimated total-cost node first, combining path cost g(n) with heuristic h(n) toward the goal.
- **A B Testing:** A/B testing compares product variants on live users with ethical guardrails and pre-registered metrics.
- **A B Tests:** A/B tests compare prompt or context variants on live traffic with guardrail metrics.
- **Ablations:** Ablations remove components to measure contribution—essential for judging which mechanism drives reported gains.
- **Abstention:** Abstention lets a system refuse or defer when confidence is insufficient, routing cases to humans or safer paths.
- **Acceptance Criteria:** Acceptance criteria are pass/fail conditions for feature completion—testable, unambiguous, tied to user value.
- **Accessibility:** Accessibility ensures AI features work with screen readers, keyboard navigation, and assistive tech—not only visual chat UIs.
- **Action Spaces:** Action spaces define allowed agent operations—click, type, scroll, API call—with granularity affecting reliability.
- **Activations:** Activation functions introduce nonlinearity—ReLU, GELU, sigmoid—without which deep networks collapse to linear maps.
- **Adaptive Rag:** Adaptive RAG chooses retrieval depth, query rewrite, or no retrieval based on question type and confidence.
- **Adoption:** Adoption tracks who uses the feature, how often, and whether usage persists after novelty fades.
- **Adversarial Tests:** Adversarial tests probe injection, jailbreaks, edge inputs, and abuse scenarios.
- **Agency:** Agency is goal-directed action selection in a loop—observe, decide, act—rather than a single model call.
- **Ai Coding Agents:** AI coding agents autonomously edit repositories given goals, tools, and constraints.
- **Ai Gateways:** AI gateways centralize model access with auth, rate limits, logging, routing, and policy enforcement for enterprise teams.
- **Ai Inventory:** AI inventory catalogs models, datasets, prompts, and features with owners, risk tier, and dependencies.
- **Aks And Functions:** AKS and Azure Functions run containerized model servers and event-driven AI glue code on Azure.
- **Amazon Bedrock:** Amazon Bedrock provides managed access to foundation models from multiple providers via unified AWS APIs with IAM integration and private networking.
- **Ambiguity:** Ambiguity arises when the same text supports multiple interpretations without disambiguating context.
- **Ann Indexes:** Approximate nearest neighbor indexes—HNSW, IVF, LSH—trade recall for speed at million-plus scale.
- **Answer Validation:** Answer validation runs programmatic checks—schema, arithmetic, citation alignment—on model outputs before display.
- **Approval Gates:** Approval gates pause execution until authorized humans confirm high-impact actions.
- **Attention Masks:** Attention masks zero out disallowed positions—future tokens in decoding, padding, or cross-segment boundaries.
- **Audit:** Audit logs record who accessed which models, documents, and tools with immutable retention for compliance.
- **Audit Evidence:** Audit evidence collects eval reports, approvals, change logs, and incident records demonstrating controlled AI delivery.
- **Authentication:** Authentication verifies identity of users, clients, and services before access to models, tools, or data.
- **Authorization:** Authorization ensures retrieved and acted-upon data respects user permissions—not just authentication.
- **Autoencoders:** Autoencoders learn compressed representations by reconstructing inputs through a bottleneck layer.
- **Autonomy:** Autonomy is how much discretion the system has to choose actions without human approval.
- **Autoscaling:** Autoscaling adjusts inference replica count based on CPU, GPU utilization, or queue depth.
- **Azure Ai Foundry:** Azure AI Foundry is Microsoft's unified portal for model deployment, fine-tuning, evaluation, and agent tooling integrated with Azure services.
- **Azure Ai Search:** Azure AI Search provides hybrid lexical-vector search, semantic ranker, and skill pipelines for RAG on Azure.
- **Azure Openai:** Azure OpenAI Service hosts OpenAI models in Azure regions with private networking, content filters, and Entra ID auth.
- **Backpropagation:** Backpropagation applies the chain rule to compute gradients through layered computations efficiently.
- **Backtracking:** Backtracking abandons partial solutions that fail constraints and returns to earlier choices.
- **Baseline Workflow:** Baseline workflow documents how users solve the task today—time, errors, tools—before AI intervention.
- **Baselines:** Baselines are simple reference methods—majority class, linear model, keyword rules—that quantify what complexity must beat.
- **Batching:** Batching groups requests to amortize GPU kernel overhead, improving throughput at possible latency cost.
- **Behavior Versus Knowledge:** Behavior changes how the model acts—tone, format, policy—while knowledge is factual content.
- **Benchmarks:** Benchmarks standardize task comparisons—MMLU, HumanEval, BEIR—but may not reflect your production distribution.
- **Best Of N:** Best-of-N generates N candidates and selects the best by a scorer or verifier.
- **Bias And Variance:** Bias is systematic underfitting from overly simple models; variance is sensitivity to training noise from overly complex ones.
- **Bm25:** BM25 ranks documents by weighted term frequency with length normalization and term-frequency saturation.
- **Bottlenecks:** Information bottlenecks force compressive representations—fixed-size context vectors or limited bandwidth channels.
- **Bounded Rationality:** Bounded rationality acknowledges limited compute, time, memory, and information—systems must satisfice within budgets.
- **Bpe:** Byte-pair encoding iteratively merges frequent symbol pairs to build a subword vocabulary from corpus statistics.
- **Breadth First Search:** Breadth-first search expands nodes level by level, guaranteeing shortest path in unweighted graphs.
- **Budgets:** Budgets cap tokens, tool calls, wall time, or dollars per task or session.
- **Build Versus Buy:** Build versus buy weighs custom AI development against vendor APIs and platforms on control, cost, and time-to-value.
- **Caching:** Caching stores prompt prefixes, embeddings, or completions to cut latency and cost.
- **Calibration:** Calibration means predicted probabilities align with observed frequencies—70% confidence should be right about 70% of the time.
- **Canaries:** Canaries route small traffic percentage to new versions before full rollout.
- **Cancellation:** Cancellation stops in-flight agent work cleanly—revoke leases, abort tool calls, compensate partial effects.
- **Capability Decomposition:** Capability decomposition splits intelligence into perception, memory, learning, planning, and action so teams can own, test, and debug each part.
- **Checkpoints:** Checkpoints persist durable agent state so interrupted runs resume without repeating side effects.
- **Chunking:** Chunking splits documents into index units sized for retrieval precision and generation context.
- **Citation Precision:** Citation precision measures whether cited sources actually support the adjacent claims.
- **Citations:** Citations link UI claims to source passages users can verify.
- **Classification:** Classification assigns inputs to discrete categories via scores converted to labels.
- **Cloud Iam:** Google Cloud IAM binds roles to identities for least-privilege access to Vertex, Storage, and BigQuery in AI pipelines.
- **Cloud Run And Gke:** Cloud Run and GKE deploy serverless containers and Kubernetes GPU workloads on Google Cloud.
- **Cloudwatch And Iam:** CloudWatch and IAM deliver AWS monitoring, alerting, and access control for AI workloads—metrics, logs, roles, policies.
- **Clustering:** Clustering groups unlabeled points by similarity—k-means, hierarchical, or density methods.
- **Code Review:** Code review evaluates correctness, security, and maintainability of changes—including agent-written code.
- **Compensation:** Compensation undo or offsets partial effects when later steps fail—Saga pattern for agents.
- **Component Evals:** Component evals test retrieval, generation, tools, and UX stages independently before end-to-end runs.
- **Compression:** Context compression summarizes, extracts, or prunes evidence to fit token limits while preserving decision-critical facts.
- **Computer Use:** Computer use agents perceive screens and emit mouse/keyboard actions to complete software tasks.
- **Conditioning:** Conditioning steers generation with extra inputs—text, masks, ControlNet edges, brand assets.
- **Confidence Intervals:** Confidence intervals quantify uncertainty in metric estimates from finite eval sets.
- **Confusion Matrix:** A confusion matrix counts predicted versus actual classes, exposing which errors dominate.
- **Consensus:** Consensus protocols align multiple agents on a decision before action—voting, debate, or judge model.
- **Constraints:** Constraints specify forbidden actions, length limits, formats, and scope boundaries in prompts.
- **Containers:** Containers package model servers with dependencies for reproducible deployment across environments.
- **Contamination:** Contamination occurs when eval examples leak into training data, inflating benchmark scores.
- **Context Assembly:** Context assembly is the pipeline that gathers instructions, state, evidence, tools, and examples into the final prompt.
- **Context Files:** Context files—.
- **Context Packing:** Context packing fits selected passages into the token window respecting priority, citation needs, and truncation rules.
- **Context Poisoning:** Context poisoning inserts false or misleading evidence into retrieval or memory stores to manipulate outputs.
- **Context Traces:** Context traces log the assembled prompt sections, token counts, and sources for debugging and compliance.
- **Context Windows:** Context windows cap tokens the model attends to in one forward pass—prompt, evidence, tools, and output compete for this budget.
- **Continual Learning:** Continual learning updates models on new data without catastrophic forgetting of prior tasks.
- **Continuous Evaluation:** Continuous evaluation runs production or shadow traffic against eval suites to detect drift post-release.
- **Contract Tests:** Contract tests verify integrations between services—API schemas, tool responses—without full end-to-end runs.
- **Control:** Control mechanisms—approvals, rate limits, tool allowlists— constrain agent behavior within safe envelopes.
- **Coordination:** Coordination synchronizes multiple agents—shared queues, locks, message passing—to avoid conflicting actions.
- **Corpora:** Corpora are curated text collections whose composition, licensing, and bias shape every downstream model.
- **Correction:** Correction flows let users fix wrong AI outputs and feed improvements—labels, prompts, or models.
- **Cosine Similarity:** Cosine similarity measures the angle between vectors, ignoring magnitude—standard for normalized embeddings in retrieval.
- **Cost Quality Curves:** Cost-quality curves plot spend—tokens, GPU seconds, API dollars—against task metrics.
- **Critique:** Critique models or rubrics evaluate drafts and suggest fixes before finalization.
- **Cross Validation:** Cross-validation rotates train and validation folds to estimate performance variance with limited data.
- **Data Cards:** Data cards document dataset sources, collection, demographics, limitations, and recommended uses—parallel to model cards.
- **Data Curation:** Data curation selects, cleans, and balances training examples for quality over quantity.
- **Data Exfiltration:** Data exfiltration via AI occurs when prompts or tools leak secrets, PII, or restricted docs to unauthorized parties.
- **Data Leakage:** Data leakage lets information from the target or future timesteps into features or labels during training.
- **Data Mixtures:** Data mixtures blend corpora—web, code, books, dialog—at tuned ratios during pretraining.
- **Data Provenance:** Data provenance records origin, transformations, timestamps, and responsible parties for each document.
- **Data Residency:** Data residency restricts processing and storage to approved geographic regions for legal compliance.
- **Data Validation:** Data validation checks schema, ranges, distributions, and freshness of incoming data before training or inference.
- **Decision Thresholds:** Decision thresholds turn continuous scores into actions—approve, escalate, or abstain.
- **Decomposition:** Decomposition breaks complex tasks into subtasks with clearer stopping criteria and verifiable intermediate results.
- **Deduplication:** Deduplication removes near-duplicate training examples that inflate metrics and memorization.
- **Deep Learning:** Deep learning stacks differentiable layers that learn hierarchical features from raw inputs.
- **Delegation:** Delegation assigns subtasks to specialized agents or tools with scoped permissions.
- **Delimiters:** Delimiters—XML tags, markdown fences, triple quotes—separate instructions from data so models parse structure reliably.
- **Dense Retrieval:** Dense retrieval embeds queries and documents into the same vector space and returns nearest neighbors by similarity.
- **Dependencies:** Dependencies constrain execution order—step B requires output or state from step A.
- **Deterministic Metrics:** Deterministic metrics—exact match, F1 on spans, JSON validity—give reproducible scores without sampling variance.
- **Diarization:** Diarization labels who spoke when in multi-speaker audio—essential for meetings and support calls.
- **Diffusion:** Diffusion models generate images by iterative denoising from noise, conditioning on text or layout.
- **Dimensionality Reduction:** Dimensionality reduction projects high-dimensional data to fewer dimensions for visualization, compression, or denoising—PCA, t-SNE, UMAP.
- **Discourse:** Discourse connects sentences across turns and documents—coreference, topic continuity, rhetorical structure.
- **Distillation:** Distillation trains smaller student models to mimic larger teachers, trading capability for cost and speed.
- **Distribution Shift:** Distribution shift occurs when deployment data differs from training data in language, demographics, seasonality, or product mix.
- **Diversity:** Diversity in context selection avoids redundant passages that waste tokens on repeated facts.
- **Document Ai:** Document AI pipelines combine OCR, layout, extraction, and validation for structured data from unstructured files.
- **Dot Product:** Dot product measures alignment between vectors—used in attention scores and similarity when magnitudes carry signal.
- **Dpo:** Direct Preference Optimization aligns models from pairwise preferences without explicit reward model training.
- **Drift:** Drift is change in input or label distributions over time—covariate, prior, or concept drift.
- **Durable Execution:** Durable execution persists workflow state across process restarts and deploys—Temporal, Step Functions patterns.
- **Embedding Evaluation:** Embedding evaluation measures retrieval quality—recall, MRR, nDCG—on realistic queries with hard negatives.
- **End To End Evals:** End-to-end evals measure full pipeline outcomes on realistic inputs including latency and cost.
- **Entra Id And Monitor:** Microsoft Entra ID and Azure Monitor provide identity, RBAC, and observability for Azure AI workloads.
- **Entropy:** Entropy measures uncertainty or information content in a distribution—high when outcomes are evenly spread, low when one dominates.
- **Episodic Memory:** Episodic memory stores past run trajectories—what was tried, what failed—for future reference within or across sessions.
- **Eval Datasets:** Eval datasets are labeled or rubric-scored cases representing production risks and happy paths.
- **Evaluation Specs:** Evaluation specs define datasets, metrics, slices, and release thresholds before shipping.
- **Expected Cost:** Expected cost combines probabilities of outcomes with their business costs to rank decisions.
- **Experiment Tracking:** Experiment tracking logs hyperparameters, data versions, metrics, and artifacts for every training run.
- **Expert Systems:** Expert systems capture domain heuristics in if-then rules curated by specialists, often with explanation traces.
- **Fairness:** Fairness examines disparate performance or harm across demographic or regional groups.
- **Faithfulness:** Faithfulness checks that generated statements are entailed by retrieved evidence, not hallucinated additions.
- **Fallbacks:** Fallbacks switch to alternate models, cached answers, or human handoff when primary path fails.
- **Feasibility:** Feasibility assesses whether data, latency, risk, and model capability can meet requirements—not whether a demo works once.
- **Features And Labels:** Features are inputs; labels are supervised targets—both must be available at the decision time you actually deploy.
- **Feedback:** Feedback closes the loop: outcomes from actions update beliefs, models, or policies for subsequent decisions.
- **Few Shot Examples:** Few-shot examples demonstrate desired input–output patterns inside the prompt.
- **Fine Tuning:** Fine-tuning adapts pretrained weights with supervised or preference data when prompts and RAG cannot stabilize behavior.
- **Finops:** FinOps tracks and optimizes AI spend—tokens, GPU hours, API fees—against business value.
- **Freshness:** Freshness policies define acceptable document age, re-ingest cadence, and TTL for cached answers.
- **Function Calling:** Function calling lets models emit structured invocations with typed arguments that runtime code validates and executes.
- **Functional Specifications:** Functional specifications describe observable system behavior—inputs, outputs, errors—for builders and testers.
- **Generalization:** Generalization is performance on unseen data drawn from the deployment distribution, not memorization of training examples.
- **Goal Decomposition:** Goal decomposition maps a top-level objective into subgoals with success conditions and dependencies.
- **Goal Directed Behavior:** Goal-directed behavior means selecting actions to reduce distance to an explicit objective rather than producing unconstrained text.
- **Gold Datasets:** Gold datasets hold authoritative labels or reference outputs for evaluation.
- **Gpus:** GPUs accelerate matrix operations for training and inference; memory capacity limits model size and batch.
- **Gradient Descent:** Gradient descent adjusts parameters in the direction that most reduces loss, using gradients computed from training examples.
- **Graph Rag:** Graph RAG combines knowledge graphs with retrieval so multi-hop relations traverse explicit edges.
- **Grounded Generation:** Grounded generation conditions answers strictly on provided evidence, refusing when support is insufficient.
- **Grounding:** Grounding ties model statements to verifiable evidence—retrieved passages, database rows, tool outputs.
- **Hard Negatives:** Hard negatives are plausible but incorrect passages that confuse retrievers—essential for training and evaluation realism.
- **Heuristics:** Heuristics estimate remaining cost or promise of partial solutions to guide search toward promising branches.
- **Human Evaluation:** Human evaluation labels outputs quality when automation cannot capture nuance or safety.
- **Human Oversight:** Human oversight defines when and how people supervise agents—monitoring dashboards, escalation queues, kill switches.
- **Human Review:** Human review inserts expert judgment for high-impact or low-confidence decisions.
- **Hybrid Search:** Hybrid search combines lexical and dense signals—often via reciprocal rank fusion—when neither alone covers identifiers and paraphrases.
- **Idempotency:** Idempotent tools produce the same effect when called repeatedly with the same idempotency key.
- **Identity:** Identity establishes who users and services are—SSO, service principals, workload identity—for AI data access.
- **Impact Assessment:** Impact assessment evaluates consequences of deploying AI on people, rights, and society before high-risk launch.
- **Incident Response:** Incident response defines detect, triage, mitigate, communicate, and postmortem for AI failures—hallucination harm, data leak, outage.
- **Inference:** Inference applies a trained model to new inputs to produce predictions or generations.
- **Instruction Conflict:** Instruction conflict occurs when system, developer, user, or retrieved text give incompatible directives.
- **Instruction Hierarchy:** Instruction hierarchy ranks system, developer, and user messages so lower-priority text cannot override safety or policy.
- **Instruction Tuning:** Instruction tuning fine-tunes models on prompt–response pairs covering diverse tasks, improving zero-shot instruction following.
- **Inter Rater Agreement:** Inter-rater agreement measures how consistently multiple human graders apply rubrics—Cohen's kappa, Krippendorff's alpha.
- **Jobs To Be Done:** Jobs-to-be-done frames what users hire a product to accomplish, not which technology it uses.
- **Json Schema:** JSON Schema declares required fields, types, and constraints that validators enforce after model generation.
- **Keys:** Keys are attention projections indexed for lookup—compatible queries receive high weights.
- **Knowledge Freshness:** Knowledge freshness measures how current stored facts are relative to the real world.
- **Knowledge Representation:** Knowledge representation chooses how facts, relations, and uncertainty are stored—graphs, frames, schemas, or vectors.
- **Kv Cache:** The KV cache stores key and value tensors for prior tokens during autoregressive decoding, avoiding recomputation of the prefix.
- **Lambda And Eks:** AWS Lambda and EKS provide serverless functions and Kubernetes clusters for AI orchestration, agents, and custom servers.
- **Latency:** Latency is time from request to usable response—dominated by model, retrieval, tools, and serialization.
- **Latent Space:** Latent space in generative models compresses images to lower-dimensional representations for efficient editing and generation.
- **Layout Models:** Layout models detect reading order, tables, figures, and headings in documents beyond raw OCR boxes.
- **Leases:** Leases grant temporary exclusive ownership of a resource—document, ticket, shard—preventing duplicate processing.
- **Llm Judges:** LLM judges automate scoring using rubrics but must be calibrated against humans to avoid systematic bias.
- **Logits:** Logits are raw pre-softmax scores over the vocabulary for the next token.
- **Long Context:** Long context models attend to hundred-thousand-plus tokens in one window—reducing need for retrieval but not eliminating cost or lost-in-middle effects.
- **Long Term Memory:** Long-term memory stores durable facts—preferences, past resolutions—retrieved selectively for future sessions.
- **Lora:** LoRA fine-tunes low-rank adapter matrices in attention layers, reducing trainable parameters versus full fine-tuning.
- **Loss Functions:** Loss functions score how wrong predictions are and drive optimization—cross-entropy for classes, MSE for regression, custom losses for ranking.
- **Lstms:** LSTMs add gating to RNNs to mitigate vanishing gradients and capture longer dependencies than plain RNNs.
- **Matrix Transformations:** Matrix transformations apply linear maps that rotate, scale, or project vector spaces—core to neural layers and attention projections.
- **Mcp:** Model Context Protocol standardizes how clients discover tools, resources, and prompts from servers.
- **Memory:** Memory in frontier systems spans working, episodic, and semantic stores beyond context windows—implementation varies widely.
- **Memory Retrieval:** Memory retrieval selects relevant past facts given the current query—vector search, keyword, or structured lookup.
- **Metadata:** Metadata tags documents with tenant, date, author, permissions, and type for filtering and ranking.
- **Metadata Filtering:** Metadata filtering restricts vector or lexical search by tenant, date, permission, or document type before or after similarity scoring.
- **Mixture Of Experts:** Mixture-of-experts activates subsets of parameters per token, scaling capacity without proportional compute.
- **Mlp Blocks:** MLP blocks apply position-wise feed-forward networks after attention, adding nonlinear capacity per token.
- **Model Cards:** Model cards document intended use, training data, limitations, metrics, and ethical considerations for a model version.
- **Model Catalog:** Model catalog lists approved models with risk tier, eval status, and allowed use cases for developers.
- **Model Registry:** A model registry stores versioned models with stage labels—staging, production, archived—and metadata for audit.
- **Model Routing:** Model routing directs requests to appropriate models by task, risk, cost, or latency policy.
- **Model Selection:** Model selection matches capabilities, cost, latency, license, and risk to task requirements—not brand prestige.
- **Monitoring:** Monitoring observes live inputs, outputs, latency, errors, and business metrics continuously.
- **Multi Head Attention:** Multi-head attention runs several attention operations in parallel with separate projections, letting different heads capture diverse relations.
- **Multi Hop Retrieval:** Multi-hop retrieval gathers evidence across sequential lookups when no single passage contains the answer.
- **Multi Tenancy:** Multi-tenancy isolates customer data, indexes, quotas, and configs in shared AI platforms.
- **Multilingual Models:** Multilingual models share parameters across languages, enabling cross-lingual retrieval and generation.
- **Multimodal Models:** Multimodal models ingest text, images, audio, or video in shared architectures for joint understanding or generation.
- **N Grams:** N-gram models predict tokens from local history of n−1 prior tokens—simple, fast, and limited to short context.
- **Nearest Neighbors:** Nearest-neighbor search returns the closest vectors to a query by a chosen metric.
- **Neurons And Layers:** Neurons apply activations to weighted sums; layers stack these transforms into composable functions.
- **Normalization:** Text normalization lowercases, strips diacritics, standardizes whitespace, and canonicalizes equivalents before indexing or tokenization.
- **Ocr:** OCR extracts text from scanned images and photos, introducing recognition errors that propagate to chunks and answers.
- **One Hot Vectors:** One-hot vectors encode categorical items as sparse binary indicators—simple but high-dimensional and semantically blind.
- **Open Weights:** Open-weights models publish parameters for local deployment, fine-tuning, and inspection—versus API-only access.
- **Opensearch:** Amazon OpenSearch supports lexical, vector, and hybrid search with k-NN indexes for RAG on AWS.
- **Optimization:** Optimization finds parameters that minimize loss—SGD, Adam, learning-rate schedules, and batch size interact with convergence speed and final quality.
- **Optimizers:** Optimizers like Adam, AdamW, and SGD with momentum adapt update rules beyond vanilla gradient descent.
- **Parent Child Retrieval:** Parent–child retrieval indexes small child chunks for precision but returns parent sections for generation context.
- **Parsing:** Parsing converts documents—PDF, HTML, DOCX—into clean text and structure for indexing.
- **Permissions:** Permissions bind tools and data access to authenticated identities and roles.
- **Plan Act Observe:** Plan–act–observe separates choosing the next action, executing it, and recording observations that update state.
- **Plan Representation:** Plan representation encodes steps, preconditions, effects, and dependencies in structures machines can validate—DAGs, STRIPS, or typed JSON plans.
- **Planner Executor:** Planner–executor splits strategic planning from tactical execution, often with different models or prompts.
- **Planning:** Planning sequences actions to reach a goal given a model of state transitions, costs, and constraints.
- **Platform Engineering:** Platform engineering builds self-service AI infrastructure—gateways, eval harnesses, templates—so product teams ship faster safely.
- **Portable Interfaces:** Portable interfaces—OpenAI-compatible APIs, OTel traces, standard embedding dims—reduce lock-in across clouds.
- **Position:** Position information tells transformers token order since self-attention is permutation-invariant without it.
- **Pragmatics:** Pragmatics interprets meaning in context—speaker intent, implicature, and shared knowledge.
- **Precision And Recall:** Precision is correctness among positive predictions; recall is coverage of actual positives.
- **Pretraining Objectives:** Pretraining objectives define self-supervised targets—causal LM, masked LM, denoising—that shape what models learn from raw text.
- **Primary Sources:** Primary sources are original papers, specs, and official docs—not summaries or hype threads—for technical claims.
- **Privacy:** Privacy limits collection, retention, and exposure of personal data in training, logs, and outputs.
- **Probability:** Probability quantifies uncertainty over outcomes, enabling expectations, risk calculations, and principled decisions under incomplete information.
- **Problem Framing:** Problem framing defines the unit of prediction, target label, decision, population, and time boundary before choosing algorithms.
- **Prompt Injection:** Prompt injection embeds hostile instructions in untrusted content that models may follow instead of trusted policy.
- **Prompt Specs:** Prompt specs version instructions, constraints, examples, and expected behaviors like API contracts.
- **Prompt Versioning:** Prompt versioning tracks template changes with IDs, authors, and diffs like code.
- **Prompting:** Prompting steers model behavior at inference via instructions and examples without weight updates.
- **Provenance:** Provenance for generated media records model, prompt, timestamp, and user for copyright and authenticity disputes.
- **Qlora:** QLoRA combines quantization of base weights with LoRA adapters for fine-tuning on consumer GPUs.
- **Quantization:** Quantization reduces weight precision—INT8, INT4—to cut memory and increase throughput with small quality trade-offs.
- **Queries:** In attention, queries represent what information a position seeks from other positions.
- **Query Rewriting:** Query rewriting transforms requests via expansion, decomposition, or HyDE before retrieval to close vocabulary gaps.
- **Queues:** Queues decouple agent work submission from processing, smoothing load and enabling retries.
- **Rag:** Retrieval-augmented generation retrieves external evidence at query time and conditions generation on it.
- **Ranking:** Ranking orders candidates—retrieved passages or context sections—by relevance, recency, or priority before the model sees them.
- **Rational Agents:** Rational agents choose actions that maximize expected utility toward a goal given perceived state and known constraints.
- **Re Indexing:** Re-indexing rebuilds search indexes after embedding model or chunking changes.
- **Reasoning Models:** Reasoning models allocate extra inference compute—long chains, self-checks—for math, code, and planning tasks.
- **Reciprocal Rank Fusion:** Reciprocal rank fusion merges ranked lists by summing 1/(k + rank) per document across retrievers.
- **Recovery:** Recovery restores consistent state after crashes, tool failures, or partial commits.
- **Reflection:** Reflection lets agents critique recent actions and adjust strategy—retry, replan, or escalate.
- **Regression:** Regression predicts continuous targets—latency, revenue, temperature—by minimizing loss over numeric outputs.
- **Regression Evaluation:** Regression evaluation re-runs fixed test suites after prompt or context changes to catch quality drops.
- **Regularization:** Regularization penalizes complexity—L2 weight decay, dropout, early stopping—to improve generalization.
- **Release Gates:** Release gates block deployment until eval, security, and performance criteria pass.
- **Repair:** Repair loops attempt to fix invalid model outputs—re-prompting with errors, partial parsing, or constrained retries.
- **Replanning:** Replanning updates the action sequence when observations invalidate assumptions.
- **Repo Instructions:** Repo instructions—AGENTS.
- **Representation Learning:** Representation learning discovers features automatically instead of hand-engineering them.
- **Reproduction:** Reproduction reruns experiments with disclosed details to verify claims before betting architecture on results.
- **Rerankers:** Rerankers rescore top-k candidates with cross-attention models more accurate than bi-encoders alone.
- **Residual Connections:** Residual connections add layer inputs to outputs, easing gradient flow through deep stacks.
- **Resilience:** Resilience designs for partial failure—retries, circuit breakers, multi-region—without total service loss.
- **Resources:** MCP resources expose readable data—files, records, configs—to clients with URI identifiers.
- **Retries:** Retries re-invoke models or tools after transient failures or validation misses, with backoff and limits.
- **Retrieval:** Retrieval selects candidate evidence from a corpus given a query before ranking and generation.
- **Retrieval Metrics:** Retrieval metrics—recall@k, MRR, nDCG—measure candidate set quality before generation sees it.
- **Reviewer:** Reviewer pattern inserts a critique pass before delivery or irreversible actions.
- **Risk Tiers:** Risk tiers classify AI systems by potential harm—low, medium, high—driving eval depth, approval path, and monitoring.
- **Rnns:** Recurrent neural networks process sequences step by step, maintaining hidden state across time.
- **Robotics Interfaces:** Robotics interfaces connect AI planners to sensors and actuators with safety interlocks and real-time constraints.
- **Roi:** ROI compares value gained—time saved, revenue, deflected tickets—to total cost—build, inference, review, incidents.
- **Role Isolation:** Role isolation restricts each agent to tools and data matching its role, limiting blast radius of compromise or error.
- **Roles:** Roles—system, user, assistant, tool—label message provenance and expected behavior in chat APIs.
- **Routing:** Routing directs requests to models, tools, or strategies by task type, risk, or budget.
- **Rubrics:** Rubrics score qualitative outputs against anchored criteria with examples at each level.
- **Sagemaker:** Amazon SageMaker covers ML training, tuning, hosting, and monitoring for custom and foundation models on AWS.
- **Sampling:** Sampling draws next tokens from the predicted distribution rather than always taking the argmax.
- **Sandboxing:** Sandboxing isolates code execution, browsing, or file access in restricted environments with network and filesystem limits.
- **Scaled Dot Product:** Scaled dot-product attention computes softmax(QKᵀ/√d)V, scaling dot products to stable gradients.
- **Scaling Laws:** Scaling laws relate model size, data, and compute to predictable loss improvements—guiding budget allocation.
- **Search:** Search explores a space of partial solutions—plans, code candidates, tool sequences—guided by heuristics and budgets.
- **Segmentation:** Segmentation splits text into sentences, paragraphs, or utterances for processing pipelines.
- **Self Consistency:** Self-consistency samples multiple reasoning paths and aggregates answers by majority vote.
- **Self Supervision:** Self-supervision creates training signal from the data itself—mask prediction, contrastive pairs—without manual labels.
- **Semantics:** Semantics concerns meaning—entities, relations, entailment—not just form.
- **Sentence Embeddings:** Sentence embeddings encode whole utterances into vectors for semantic search and clustering.
- **Sentencepiece:** SentencePiece trains subword models directly on raw text without pre-tokenization, simplifying multilingual pipelines.
- **Seq2seq:** Sequence-to-sequence models map input sequences to output sequences via encoder–decoder architectures.
- **Service Catalog:** Service catalog lists internal AI products—approved models, RAG templates, tools—for self-service discovery.
- **Session Memory:** Session memory persists within a conversation—recent turns, pending clarifications—without long-term storage.
- **Sft:** Supervised fine-tuning trains on input–output pairs to imitate desired behaviors on similar tasks.
- **Shared Retrieval:** Shared retrieval services provide governed indexes, embedding pipelines, and search APIs reused across products.
