# Glossary

**Agent:** A stateful system that selects actions toward a goal in a loop.

**Attention:** Content-dependent weighting used to route information between representations.

**Autoregressive generation:** Producing a sequence by repeatedly predicting the next unit conditioned on prior context.

**Benchmark:** A standardized dataset and measurement procedure; useful evidence but not a substitute for task-specific evaluation.

**Checkpoint:** A saved model state or workflow state from which work can continue.

**Chunk:** A retrievable content unit created during ingestion.

**Context:** Information available to a model for the current inference request.

**Context window:** The maximum represented sequence length accepted or produced in one inference operation.

**Embedding:** A vector representation learned to preserve useful relationships.

**Evaluation harness:** Software that runs cases, records versions and outputs, calculates metrics, and enforces thresholds.

**Fine-tuning:** Updating model parameters using task- or behavior-specific data after pretraining.

**Foundation model:** A broadly trained model intended to support many downstream tasks.

**Grounding:** Constraining or supporting output with identifiable evidence, state, or tools.

**Hallucination:** Generated content that is unsupported, incorrect, or inconsistent with required evidence.

**Harness:** The execution environment around a model, including context, tools, permissions, state, retries, traces, and verification.

**Inference:** Running a trained model to produce representations or predictions.

**KV cache:** Stored attention keys and values that avoid recomputing earlier sequence positions during generation.

**LLM judge:** A model used to apply an evaluation rubric; it requires calibration and monitoring like any other evaluator.

**LoRA:** Parameter-efficient adaptation that learns low-rank updates while freezing most original model weights.

**MCP:** Model Context Protocol, a standard for exposing tools, resources, and related capabilities to compatible clients.

**Memory:** Persisted or selected state reconstructed into the context or control flow of a later step.

**Model routing:** Selecting a model or execution path based on task, risk, quality, availability, latency, or cost.

**Parameter:** A learned numeric value in a model; weights are a major class of parameters.

**Prompt:** Instructions and content presented to a generative model, usually as part of a larger constructed context.

**Prompt injection:** Untrusted content attempting to alter instructions or cause unauthorized behavior.

**Quantization:** Representing model values with lower precision to reduce memory and often improve inference efficiency.

**RAG:** Retrieval-augmented generation, in which selected external evidence is included during generation.

**Reranker:** A model or algorithm that reorders retrieved candidates using a more precise relevance signal.

**Skill:** A reusable package of procedural instructions, examples, and sometimes scripts or assets for a bounded task class.

**Structured output:** Model output constrained to a machine-readable schema and validated before use.

**Token:** A discrete unit produced by a tokenizer and processed or generated by a language model.

**Tool calling:** A model producing a typed request for software to execute outside the model.

**Training:** Optimizing model parameters against data and an objective.

**Transformer:** A neural architecture built around attention, feed-forward transformations, residual paths, and normalization.

**Vector database:** A storage and indexing system optimized for nearest-neighbor search over vectors, often with metadata filtering.

**Workflow:** An explicitly controlled sequence or graph of steps; it may contain model calls without becoming an agent.
