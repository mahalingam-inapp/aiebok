# Real-world Casebook

Use these cases to practice reading the evidence behind an AI decision. Each field note starts with a published account, then asks you to make a decision about a comparable system. The exercises are fictional. Their purpose is to make the reasoning testable.

| Case | What to examine |
|---|---|
| [A chatbot answer that changed a travel decision](bereavement-fares.md) | Policy conflicts, evidence, and a customer handoff |
| [What changed for customer support workers](support-assistants.md) | Benefits by experience level and the work of reviewing answers |
| [The errors a face-matching average hides](face-matching.md) | False positives, thresholds, and evidence by group |
| [Who gets left out of a transcript?](speech-recognition.md) | Speech error by slice and the consequences of a missed phrase |
| [When a better-liked model got harder to trust](model-behavior-rollback.md) | Behavioral evaluation, user feedback, and rollback |
| [Two studies measured two different coding jobs](coding-productivity.md) | Time spent writing, reviewing, and finishing a change |
| [Two zones and one deletion boundary](unisuper-recovery.md) | Recovery from a shared control-plane failure |
| [A feature file takes down a healthy service](feature-file-outage.md) | Configuration contracts, canary rollout, and recovery |
| [Why GitHub paused queued work](paused-jobs.md) | Durable workflow state, replay, and expiry |
